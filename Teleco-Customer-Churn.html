Task 1 explanation¶

Explanation: loading the data and handling data types

This step loads the Telco Customer Churn dataset and prepares it for analysis.

  1. Inspecting the data. The dataset has 7,043 customers and 21 columns. There are no duplicate rows or duplicate customer IDs, and isnull() reports no missing values.

  2. Fixing TotalCharges. This column was stored as text (object) instead of numbers, because some cells contained blank spaces. I converted it to numbers with pd.to_numeric(errors="coerce"), which turns blanks into missing values. This revealed 11 hidden missing values.

3.	Understanding the missing values. All 11 customers have a tenure of 0, meaning they had just joined and hadn't been billed yet, so no total charge existed.

4.	Imputation. I filled the missing values with the median of the column, because the median is not affected by extreme values.
    
5.	Result. TotalCharges is now a numeric (float64) column with no missing values, so it can be used in analysis and modelling.

Task 3 explanation

Explanation: preprocessing and feature encoding

Machine learning models need numbers, so I prepared the data in four steps. I dropped customerID (just an identifier) and the text Churn column (it is the answer, so keeping it would leak it to the model). I one-hot encoded the categorical columns into 0/1 columns, giving 30 features, with drop_first=True to avoid redundancy. I split the data 80/20 into training and test sets, using stratify so both keep the same churn rate. Finally I scaled tenure, MonthlyCharges and TotalCharges with StandardScaler, fitting it on the training data only to avoid data leakage.

Explanation: identifying the root causes of churn¶

This step finds which customer features have the strongest influence on churn, using both trained models.

  1. Logistic Regression coefficients. Each feature gets a coefficient. A positive value means the feature increases the likelihood of churn, and a negative value means it reduces it. The larger the number, the stronger the effect.

    • Increase churn: fiber optic internet (1.219) is the strongest driver. Streaming services, electronic check payment and paperless billing also raise churn risk. • Reduce churn: two-year contracts (-1.412), longer tenure (-1.147) and one-year contracts (-0.717) are the strongest protectors. Online security, tech support and having dependents also help.

  2. Random Forest feature importance. This shows how much each feature contributes to the model's predictions, in either direction. Tenure (0.177), two-year contract (0.132), total charges (0.129) and fiber optic internet (0.086) are the most important.

  3. Conclusion. Both models agree that churn is driven mainly by short tenure, contract type and fiber optic internet service. Customers on month-to-month contracts, in their first year and using fiber optic internet are the highest-risk group. Long-term contracts and support services (online security, tech support) help retain customers.

Recommendation¶

The company should encourage new customers to move to one- or two-year contracts, investigate why fiber optic customers are unhappy (price, service quality), and promote online security and tech support add-ons.

Task 4 Explanation: Machine Learning Model Training¶

In this step I trained two classification models to predict whether a customer will churn, and compared them on the 1,409 customers held out in the test set.

  1. Logistic Regression. A simple model that gives each feature a weight and combines them into a churn probability. It is easy to interpret, because each coefficient shows whether a feature increases or reduces churn.
  2. Random Forest. A group of 300 decision trees that vote on the outcome. It can capture more complex patterns. I limited the tree depth (max_depth=8) and the minimum samples per leaf (min_samples_leaf=5) to stop it memorising the training data.
  3. Handling imbalance. Only about 26.5% of customers churn, so I used class_weight="balanced" on both models so they pay more attention to the churners.

CLV_SAVED = 500   # value of keeping one customer
CALL_COST = 20    # cost of one retention call
SUCCESS = 0.30    # chance a call keeps a customer who would leave

rows = []
for t in np.arange(0.10, 0.91, 0.05):
    pred = p_rf >= t
    tp = int((pred & (y_test == 1)).sum())
    fp = int((pred & (y_test == 0)).sum())
    fn = int((~pred & (y_test == 1)).sum())
    profit = tp * SUCCESS * CLV_SAVED - (tp + fp) * CALL_COST
    precision = tp / (tp + fp) if tp + fp else 0
    recall = tp / (tp + fn) if tp + fn else 0
    rows.append((round(t, 2), tp + fp, round(precision, 3), round(recall, 3), round(profit)))

roi = pd.DataFrame(rows, columns=["Threshold", "Calls", "Precision", "Recall", "NetProfit"])
print(roi.to_string(index=False))
best = roi.loc[roi["NetProfit"].idxmax()]
print("\nBest cutoff:", best["Threshold"], "| Net profit:", best["NetProfit"])

Task 5 explanation

Explanation: threshold modelling and ROI

The model gives each customer a churn probability, and the company must choose a cutoff for retention calls. A low cutoff catches more churners but makes more wasted calls. A high cutoff makes fewer calls but misses churners. The precision-recall curve shows this trade-off. Using assumed values (customer value 500, call cost 20, save rate 30%), I calculated net profit at each cutoff. The best cutoff is 0.25, giving 852 calls, 93% recall, 41% precision and a net profit of 35,310, which beats the default 0.50 cutoff (32,830). Profit is flat between 0.15 and 0.40, so the cutoff can be adjusted to the team's capacity.

Summary and Recommendations¶

Objective¶

Predict which customers are likely to churn, identify the root causes, and determine the best cutoff for retention calls.

Summary of Findings¶

Data preparation. The dataset has 7,043 customers and 21 columns, with no duplicate rows. TotalCharges was stored as text and contained 11 blank values, all from customers with zero tenure. I converted it to numbers and filled the blanks with the median.

Exploratory analysis. The overall churn rate is 26.5%.

  • Contract: month-to-month customers churn at 42.7%, one-year at 11.3% and two-year at 2.8%.
  • Tenure: churn falls from 47.4% in the first 12 months to 9.5% after 48 months.
  • Monthly charges: churn is lowest (10.9%) under $35 and highest (37.8%) at $70-90.

Preprocessing. I one-hot encoded the categorical variables (30 features), split the data 80/20 with stratification, and scaled the numeric columns using a scaler fitted on the training data only.

Model performance.

Model ROC-AUC Churn precision Churn recall
Logistic Regression 0.842 0.51 0.78
Random Forest 0.844 0.53 0.78

Both models perform well and similarly. The root causes of churn are short tenure, month-to-month contracts and fiber optic internet. Longer contracts and services such as online security and tech support reduce churn.

Threshold and ROI. I calculated net profit for cutoffs from 0.10 to 0.90.

  • The best cutoff is 0.25: 852 calls, 93% of churners caught (recall), 41% precision, and a net profit of **35,310.
  • This beats the default 0.50 cutoff (net profit 32,830).
  • Profit is flat between 0.15 and 0.40, so the cutoff can be adjusted to match the team's call capacity.

Recommendations¶

  1. Use a probability cutoff of about 0.25 for retention calls. A call costs little compared with the value of a saved customer, so it is worth accepting low precision to reach most churners. If call capacity is limited, raise the cutoff towards 0.40 and keep most of the profit.
  2. Move month-to-month customers onto one- or two-year contracts with discounts or loyalty offers. This is the strongest protection against churn.
  3. Focus on the first 12 months. Run onboarding and early check-in programmes for new customers, since nearly half of them leave in year one.
  4. Investigate fiber optic customers. They have the highest churn risk, so check price, speed reliability and support quality.
  5. Promote online security and tech support add-ons. Customers with these services stay longer.
  6. Encourage a switch away from electronic check payment to automatic payment methods, which are linked to lower churn.
  7. Retrain the model regularly and monitor its precision and recall on new customers.

Limitations¶

  • The ROI results depend on assumed values (customer value 500, call cost 20 and a 30% save rate). They should be replaced with the company's actual figures.
  • The model shows association, not proof of cause, so retention offers should be tested on a small group first.
  • At the best cutoff, about 6 in 10 calls go to customers who would have stayed anyway.
  • Results were measured on a held-out test set of 1,409 customers.
